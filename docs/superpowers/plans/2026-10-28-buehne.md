# Bühne – Umsetzungsplan (Stufe 1)

> **Für ausführende Agenten:** Kern (Aufgaben K1–K7) und Oberfläche (O1–O6) laufen parallel; die Schnittstellen in
> diesem Dokument sind bindend. Je Aufgabe: Test (rot) → Code (grün) → Commit. Spezifikation:
> `docs/superpowers/specs/2026-10-28-buehne-generative-oberflaeche-design.md`. Katalog:
> `kern/jarvis/buehne/katalog.json`. Stile: `kern/jarvis/buehne/stile/*.json`.

**Ziel:** Bühne über dem Chat, auf der der Assistent Ergebnisse als A2UI-Flächen aufbaut; Vorlagen, Rezepte und
Stile dauerhaft; drei Beispiele (Immobilien aus GG, Posteingang, Wetter).

**Architektur:** Kern-Paket `jarvis/buehne/` (Katalog, Speicher, Erzeuger, Manager, Werkzeuge) + WebSocket-
Ereignisse `buehne`/`buehne_aktion` + REST `/api/buehne/*`. Oberfläche `src/buehne/` (Store, Renderer, Bausteine,
Stile) + Bühne in der Konsole + Einstellungen-Reiter „Bühne“.

**Technik:** Python 3.12, jsonschema (prüfen, sonst eigene Validierung), httpx, LiteLLM über `LLMFassade`; React 18 +
TS + zustand, vitest. Keine neuen Laufzeit-Abhängigkeiten in der Oberfläche außer ggf. einem kleinen Diagramm
(SVG selbst zeichnen, kein Chart-Paket).

## Bindende Schnittstellen

### WebSocket (Ergänzung VERTRAEGE.md)

Server → Client: `{"typ": "buehne", "nachricht": <A2UI-Nachricht>}` mit `nachricht.version = "v0.9.1"` und genau einem
Schlüssel aus `createSurface {surfaceId, catalogId, theme: {stil: <stil-id>}, titel}`, `updateComponents {surfaceId,
components[]}`, `updateDataModel {surfaceId, path, value}` (path "/" = ganzes Modell; ohne `value` löschen),
`deleteSurface {surfaceId}`. Zusätzlich `{"typ": "buehne", "nachricht": {"version": "v0.9.1", "stil": <Stil-Objekt>}}`
liefert die Werte eines Stils (gesendet vor `createSurface`, wenn der Client den Stil nicht hat).
Client → Server: `{"typ": "buehne_aktion", "name", "surfaceId", "sourceComponentId", "timestamp", "context"}` und
`{"typ": "buehne_daten", "surfaceId", "path", "value"}` (Eingabefelder, zweiseitige Bindung; gesendet bei Blur/Enter).

### REST

| Methode | Pfad | Antwort |
|---|---|---|
| GET | `/api/buehne` | `{flaechen: [{surfaceId, titel, catalogId, stil, components[], daten, vorlage}], stile: [Stil…], zuordnung: {integration: stilId}}` |
| GET | `/api/buehne/vorlagen` | `[Vorlage…]` (ohne `komponenten`, mit `versionen: n`) |
| GET | `/api/buehne/vorlagen/{id}` | Vorlage vollständig |
| PUT | `/api/buehne/vorlagen/{id}` | `{name?, stil?}` → Vorlage |
| DELETE | `/api/buehne/vorlagen/{id}` | `{geloescht: true}` |
| POST | `/api/buehne/vorlagen/{id}/zurueck` | vorherige Version aktivieren → Vorlage |
| GET | `/api/buehne/rezepte` | `[Rezept…]` |
| DELETE | `/api/buehne/rezepte/{id}` | `{geloescht: true}` |
| GET | `/api/buehne/stile` | `[Stil…]` (vordefiniert + eigene) |
| POST | `/api/buehne/stile` | `{name, quelle: {art: url\|datei\|klassen\|werte, wert?, inhalt_base64?, werte?}}` → Stil (abgeleitet) |
| PUT | `/api/buehne/stile/{id}` | `{name?, werte?, vorlieben?}` → Stil (vordefinierte werden als Kopie `<id>-eigen` gespeichert) |
| DELETE | `/api/buehne/stile/{id}` | `{geloescht: true}` (nur eigene) |
| PUT | `/api/buehne/zuordnung` | `{integration: stilId}` → gesamte Zuordnung |
| POST | `/api/buehne/aktion` | wie `buehne_aktion` → `{ok, ergebnis?}` |
| DELETE | `/api/buehne/flaechen/{surfaceId}` | Fläche schließen |

### Datentypen (TS in `src/api/types.ts`, Python in `buehne/typen.py`)

```ts
export interface StilWerte { schema: 'hell' | 'dunkel'; farben: { primaer: string; akzent: string; hintergrund: string; flaeche: string; text: string; dezent: string; ok: string; warn: string; fehler: string }; schrift: { familie: string; basisgroesse: number }; rundung: number; abstand: number; dichte: 'dicht' | 'normal' | 'luftig'; schatten: 'keiner' | 'weich' | 'stark' }
export interface Stil { id: string; name: string; beschreibung?: string; quelle: { art: 'vordefiniert' | 'url' | 'datei' | 'klassen' | 'werte'; wert?: string }; werte: StilWerte; vorlieben: { liste: 'kacheln' | 'zeilen' | 'tabelle'; bildgroesse: 'klein' | 'mittel' | 'gross'; kennzahlenOben: boolean }; eigen?: boolean }
export interface Vorlage { id: string; name: string; zweck: string; version: number; protokollVersion: string; katalogId: string; komponenten?: unknown[]; datenschema?: unknown; datenquelle: { werkzeug: string; argumente: Record<string, unknown>; abbildung: Record<string, string> }; aktionen: Record<string, string>; stil: string | null; signatur: { werkzeug: string; schluessel: string[] }; erstellt: string; geaendert: string; modell?: string; versionen?: number }
export interface Rezept { id: string; name: string; art: 'werkzeug' | 'agent'; werkzeug?: string; argumentAbbildung?: Record<string, string>; auftrag?: string; bestaetigung?: string; risiko: 'lesen' | 'aendern' | 'kritisch'; vorlage: string }
export interface Flaeche { surfaceId: string; titel: string; catalogId: string; stil: string; components: unknown[]; daten: Record<string, unknown>; vorlage: string | null }
```

Abbildung (`datenquelle.abbildung`): `{ "/immobilien": "/items", "/anzahl": "/total" }` – Ziel-JSON-Pointer →
Quell-JSON-Pointer im Werkzeugergebnis (JSON); Formatierer über Suffix `|datum`, `|waehrung:EUR`, `|zahl:1`.
Werkzeugergebnisse, die kein JSON sind, landen unter `/text`.

Argumentabbildung in Rezepten: `{ "entity_id": "context.objekt_id", "text": "context.werte.text" }`.

## Kern

### K1: Katalog laden und validieren – `kern/jarvis/buehne/katalog.py`, Tests `kern/tests/buehne/test_katalog.py`
- Funktionen: `katalog_laden() -> Katalog` (`id`, `komponenten`, `limits`, `beschreibung_fuer_prompt()` mit je einem
  Beispiel), `komponenten_pruefen(komponenten) -> list[str]` (Fehlertexte: unbekannte Komponente, fehlende `root`,
  doppelte IDs, unbekannte Verweise, Zyklen, Limits, Eigenschaften mit `wert`-Typprüfung, Aktion mit ungültigem
  Namen, Image-URL nicht https/data:image), `komponenten_saeubern()` (unbekannte Eigenschaften entfernen).
- Tests: gültiges Beispiel aus dem Katalog je Komponente, je ein Verstoß pro Regel.

### K2: Speicher – `kern/jarvis/buehne/speicher.py`, Tests `test_speicher.py`
- `BuehnenSpeicher(home)`: Ordner `~/.jarvis/buehne/{vorlagen,rezepte,stile}`; `flaechen.json`, `zuordnung.json`.
  Vorlagen mit Versionen: `vorlagen/<id>.json` enthält `{aktuell: n, versionen: [{version, komponenten, datenschema,
  datenquelle, aktionen, geaendert, modell}] (max 10)}` + Kopf (`name, zweck, stil, signatur, erstellt`).
  Methoden: `vorlagen() / vorlage(id) / vorlage_anlegen(...) / vorlage_neue_version(id, ...) / vorlage_zurueck(id) /
  vorlage_aendern(id, name=, stil=) / vorlage_loeschen(id) / vorlage_fuer_signatur(werkzeug, schluessel)`;
  Rezepte analog; Stile: vordefinierte aus dem Paket (`buehne/stile/*.json`, `eigen=False`) + eigene;
  `stil(id)`, `stil_speichern(stil)`, `stil_loeschen(id)` (nur eigene), `zuordnung()`, `zuordnung_setzen(dict)`,
  `flaechen_speichern(liste)`, `flaechen_laden()`. IDs: Kleinbuchstaben/Ziffern/Bindestrich aus dem Namen, eindeutig.
- Tests: Rundreise, Versionen (11. Version verdrängt die älteste), zurück, Signatur-Treffer, vordefinierte Stile
  nicht löschbar, Zuordnung.

### K3: Abbildung und Datenmodell – `kern/jarvis/buehne/daten.py`, Tests `test_daten.py`
- `json_pointer_holen(obj, "/a/0/b")`, `json_pointer_setzen(obj, pfad, wert)`, `abbildung_anwenden(abbildung,
  ergebnis) -> datenmodell` mit Formatierern (`|datum` → ISO, `|waehrung:EUR` → Zahl bleibt Zahl + `_text`-Feld,
  `|zahl:1`), `ergebnis_parsen(text) -> Any` (JSON, sonst `{"text": …}`; Markdown-Tabellen → Zeilenobjekte),
  `signatur(werkzeug, ergebnis)` (sortierte Schlüssel der obersten Ebene bzw. der Elemente einer Liste),
  `standardvorlage(werkzeug, ergebnis, titel) -> komponenten` (Liste von Objekten → `Tabelle`, flaches Objekt →
  Kennzahlen/Zeilen, Text → `Text` Markdown).

### K4: Erzeuger – `kern/jarvis/buehne/erzeuger.py`, Tests `test_erzeuger.py` (SkriptLLM)
- `Erzeuger(llm, katalog)`: `vorlage_bauen(werkzeug, ergebnis, wunsch, stil) -> {komponenten, datenschema,
  abbildung, name, zweck}`; `vorlage_aendern(vorlage, wunsch)`; Systemprompt aus Katalogbeschreibung, Stilvorlieben,
  Regeln (flache Liste, root, Bindungen, keine URLs erfinden, Aktionen nur mit `event`), Beispiel; Ausgabe JSON
  `{name, zweck, abbildung, datenschema, komponenten}`; Schema-gebunden über `antwort_streamen(…)` mit
  `response_format` (JSON-Objekt) falls Anbieter es kann, sonst Prompt; `json_block` aus `gedaechtnis_pflege`
  wiederverwenden; Validierung → bei Fehlern zweiter Versuch mit Fehlertext; danach `standardvorlage`.
  `stil_ableiten(name, quelle, http_fabrik)`: URL laden (max 1 MB, nur Text/CSS/HTML; verlinkte CSS-Dateien bis 5
  nachladen), Kandidaten extrahieren (CSS-Variablen `--…color…`, Hex-/rgb-Farben nach Häufigkeit, `font-family`,
  `border-radius`), Modell wählt daraus Stilwerte (JSON), Validierung Hex; Datei: gleicher Weg ohne Laden;
  Klassen: Text ans Modell; Fallback `javit-dunkel` mit abgeleiteter Primärfarbe.

### K5: Manager + Werkzeuge – `kern/jarvis/buehne/manager.py`, `werkzeuge/system.py` (oder `buehne/werkzeuge.py`),
Tests `test_manager.py`
- `BuehnenManager(speicher, erzeuger, register, senden, einstellungen)`: Flächen im Speicher (`surfaceId` =
  Vorlagen-ID oder frei), `zeigen(werkzeug, argumente, titel, wunsch, integration)`: Werkzeug über Register ausführen
  (mit `freigabe_noetig`-Pfad des Agenten → Manager bekommt `ausfuehren(name, argumente)`-Rückruf vom Agenten),
  Ergebnis parsen, Signatur → Vorlage; fehlt sie → `erzeuger.vorlage_bauen`; Stil = Vorlage.stil oder
  Zuordnung[integration] oder `javit-dunkel`; senden: `stil` (falls nötig), `createSurface`, `updateComponents`,
  `updateDataModel`; Fläche merken (`flaechen_speichern`). `daten_setzen(surfaceId, daten)`, `aendern(vorlage,
  wunsch)` (neue Version + `updateComponents`), `zurueck(vorlage)`, `schliessen(surfaceId|None)`, `aktion(nachricht)`:
  Rezept suchen → `werkzeug`: Argumente aus `context` per `argumentAbbildung`, Ausführung über Rückruf (Freigaben),
  Ergebnis → wenn Vorlage der Fläche eine Datenquelle hat: neu laden und `updateDataModel`, sonst Textantwort als
  Chat-Nachricht senden (`antwort_start/ende` mit Kennung `buehne_…`); `agent`: Auftrag + Kontext als Nutzernachricht
  an `anfrage(text, quelle="buehne")`; ohne Rezept: Nachricht „Aktion „X“ auf Fläche Y mit Daten …“ an den Agenten.
  `buehne_daten`: Datenmodell aktualisieren (zweiseitige Bindung), kein Ereignis zurück.
- Werkzeuge laut Spezifikation (`buehne_zeigen`, `buehne_vorlage_aendern`, `buehne_vorlage_zurueck`,
  `buehne_daten`, `buehne_rezept_anlegen` (kritisch), `buehne_stil_ableiten`, `buehne_stil_aendern`,
  `buehne_stil_zuweisen`, `buehne_schliessen`), Bereich technisch. Systemprompt-Abschnitt „Bühne“ mit Vorlagen der
  verbundenen Integrationen (Name, Zweck, Aktionen) und Regeln.
- Tests mit Fake-Register (Werkzeug liefert JSON), SkriptLLM für den Erzeuger, Ereignisse prüfen, Aktion → Rezept →
  Werkzeug mit Argumentabbildung, `agent`-Rezept → Nachricht, Persistenz über zwei Manager-Instanzen.

### K6: Server – `server.py`, Tests `test_server.py`
- REST laut Tabelle, WebSocket `buehne_aktion`/`buehne_daten`, Einstellung `buehne: {aktiv, hoehe}` in `konfig.py`,
  Start: `flaechen_laden()` → nach Verbindung sendet der Kern die offenen Flächen (`GET /api/buehne` genügt; Client
  lädt beim Verbinden).

### K7: Beispiele + E2E – `tests/e2e/fake_llm.py` erweitern (Tool-Call `buehne_zeigen` + JSON-Vorlage), Test
`tests/e2e/test_e2e.py::test_buehne_immobilien` (Mini-MCP-Werkzeug liefert Liste → Fläche → Aktion → Rezept).
